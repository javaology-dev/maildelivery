Three Backends

Start on YAML. Scale to MySQL. Switch between them live with one command.

01

YAML

path  data/mailboxes/{uuid}.yml
mode  atomic tmp→rename
best  small & mid servers

Zero setup. Per-player files mean a single mailbox issue never affects the rest.

02

SQLite

path  data/maildelivery.db
mode  WAL · indexed
best  100–300 players

One file, no server to run. WAL mode keeps reads fast even during writes.

03

MySQL

pool  HikariCP · 10 conns
retry built-in failover
best  300+ players / network

Production pooling, connection retry, indexed lookups. Built for big networks.

Developer API

A clean API for the plugins you build on top.

Hook MailDelivery from your own plugin without forking the source. Build shops, deliveries, quest rewards, mail-based crates — the events are there.

  • GiftSendEvent — fired before a gift is sent (cancellable)
  • GiftClaimEvent — fired when a player claims a gift
  • GiftBlockEvent — fired when a player blocks another
  • GiftExpireEvent — fired when a gift expires (async)
// Hook MailDelivery from your plugin.
// Cancel sends, react to claims, build crates.

@EventHandler
public void onGiftSend(GiftSendEvent e) {
  if (shop.isShopGui(e.getSender())) {
    e.setCancelled(true);
  }
}

// Public MailDeliveryAPI class
// for cross-plugin reads and writes.
MailDeliveryAPI api = MailDelivery.getAPI();
api.sendGift(sender, target, item);
